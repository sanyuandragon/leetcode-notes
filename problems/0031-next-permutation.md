# 31. 下一个排列

## 题目信息

- 难度：中等
- 链接：https://leetcode.cn/problems/next-permutation/
- 主知识点：双指针
- 相关知识点：数组、贪心、后缀反转、原地修改
- 复习状态：`new`

## 一眼识别

看到这些信号时，应该想到本题方法：

- 要求“下一个字典序更大的排列”
- 必须原地修改，只允许常数额外空间
- 如果已经是最大排列，要变成最小排列
- 需要让数组尽量只变大一点点
- 从右往左找第一个可以增大的位置

## 解题思路

### 暴力思路

可以生成所有排列，排序后找到当前排列的下一个排列。但排列数量是 O(n!)，完全不可行，也不满足原地和常数空间要求。

### 优化关键

要得到“刚好更大一点”的排列，应该尽量保持前面的高位不变，只调整靠右的位置。

从右往左看，如果一段后缀是非递增的，例如：

```text
... 2 5 4 3 1
      ^^^^^^^
```

这段后缀已经是它自己能形成的最大字典序，单独调整它无法变大。必须找到后缀左边第一个满足：

```cpp
nums[i] < nums[i + 1]
```

的位置 `i`。这个位置就是可以被“稍微增大”的位置。

接下来在右侧后缀中，从右往左找第一个大于 `nums[i]` 的数 `nums[j]`。因为后缀是非递增的，从右往左遇到的第一个大于 `nums[i]` 的数，就是比它大的最小候选。交换后，前缀已经变大了。为了让整体尽量小，需要把 `i + 1` 到末尾的后缀反转成升序。

如果找不到这样的 `i`，说明整个数组都是非递增的，已经是最大排列，直接反转整个数组得到最小排列。

### 最终做法

1. 从右往左找到第一个 `nums[i] < nums[i + 1]` 的位置
2. 如果找到了 `i`，从右往左找到第一个 `nums[j] > nums[i]`
3. 交换 `nums[i]` 和 `nums[j]`
4. 反转 `nums[i + 1]` 到末尾
5. 如果没找到 `i`，`i == -1`，反转整个数组

## C++ 代码讲解

```cpp
class Solution {
public:
    void nextPermutation(vector<int>& nums) {
        int n = nums.size();

        int i = n - 2;
        // 从右往左找第一个下降破坏点：nums[i] < nums[i + 1]
        // i 右侧后缀保持非递增，已经是该后缀能形成的最大排列
        while (i >= 0 && nums[i] >= nums[i + 1]) {
            i--;
        }

        if (i >= 0) {
            int j = n - 1;
            // 从右往左找第一个比 nums[i] 大的数，用它来让高位刚好变大一点
            while (nums[j] <= nums[i]) {
                j--;
            }
            swap(nums[i], nums[j]);
        }

        // 交换后，后缀仍然是非递增的；反转后变成升序，使整体尽量小
        // 如果 i == -1，等价于反转整个数组，从最大排列回到最小排列
        reverse(nums.begin() + i + 1, nums.end());
    }
};
```

关键点：

- `i`：从右往左找到的第一个可以被增大的位置
- `nums[i] >= nums[i + 1]`：说明当前位置仍属于非递增后缀
- `j`：后缀中第一个大于 `nums[i]` 的位置
- `swap(nums[i], nums[j])`：让排列变大
- `reverse(nums.begin() + i + 1, nums.end())`：让变大后的后缀尽量小
- `i == -1`：整个数组非递增，已经是最大排列，反转成最小排列

循环不变量 / 状态含义：

- 第一个 `while` 结束后，`i + 1` 到末尾是非递增后缀
- 如果 `i >= 0`，说明 `nums[i]` 可以通过和后缀中更大的数交换来增大排列
- 第二个 `while` 从右往左找，找到的是后缀中大于 `nums[i]` 的最小候选
- 交换后只需要把后缀变成升序，就能得到最小的更大排列

边界处理：

- 数组长度至少为 `1`，单元素时 `i = -1`，反转单元素数组不变
- 完全降序数组找不到 `i`，最终反转整个数组
- 有重复元素时，找 `i` 要用 `>=`，找 `j` 要用 `<=`，确保严格变大
- `reverse(nums.begin() + i + 1, nums.end())` 在 `i == -1` 时正好从 `begin()` 开始

## 复杂度分析

- 时间复杂度：O(n)，最多从右往左扫描两次，再反转一次后缀
- 空间复杂度：O(1)，原地交换和反转，只使用常数个变量

## 面试讲法

可以这样讲：

下一个排列要让字典序刚好变大，所以我尽量从右侧低位开始调整。先从右往左找第一个 `nums[i] < nums[i + 1]`，它右边的后缀一定是非递增的，已经是最大状态。如果找不到这个位置，说明整个数组已经是最大排列，直接反转成最小排列。找到 `i` 后，再从右往左找第一个大于 `nums[i]` 的数，它就是能让 `nums[i]` 变大的最小候选。交换之后，高位已经变大了，最后把后缀反转成升序，让整体在变大的前提下尽量小。

可能追问：

- 为什么从右往左找 `i`：越靠右的位置越低位，调整它能让排列变化尽量小
- 为什么后缀是非递增的：如果存在上升对，第一轮扫描就会停在那里
- 为什么从右往左找 `j`：后缀非递增，从右往左第一个大于 `nums[i]` 的数就是最小的大数
- 为什么交换后要反转后缀：交换后前缀已经变大，后缀要变成最小的升序状态

## 模板沉淀

- 可复用点：从右往左找可增大的拐点，再找刚好更大的替换值，最后反转后缀

## 易错点

- 找拐点时条件要写 `nums[i] >= nums[i + 1]`，不是 `>`
- 找替换位置时要找严格大于 `nums[i]` 的数
- 交换后必须反转后缀，不能排序整个数组
- 降序数组要反转成升序数组
- 有重复元素时，比较符号写错会导致没有真正变成下一个排列
- 这题要求原地修改，不需要返回数组

## 复盘卡片

- 如果写错，优先检查：两个 `while` 的比较符号、`j` 是否从右往左找、最后是否反转 `i + 1` 到末尾
